# Phase 5 — executable, variable-size evidence under revisions

Declared before implementation and development results, 28 September 2026.
This is a bounded authored mechanism/experience study, not a natural-workload or
LLM-quality claim. It follows the phase-2 label audit and phase-4 optimizer result.

## Asset and scientific choice

Reuse the installed CPython 3.12.14 `configparser.ExtendedInterpolation` as the
unchanged downstream executor. Its native behavior, source hash and independently
authored expected strings will be checked against each other. Author small INI
section archives, requests, revisions and environment-scope metadata locally.
The [official documentation](https://docs.python.org/3.12/library/configparser.html)
and installed implementation were inspected: interpolation supports cross-section
references, local/default option lookup and escaped dollar signs. No new dataset,
encoder, neural reader, external service or model download is needed.

The question is whether selection behavior learned from earlier *executed*
configuration attempts survives new values and changed dependency structure.
Unlike fixed four-passage QA, required evidence cardinality can change. Deliver
whole sections, then render the requested value through the native interpreter.
Completion requires exact rendered output and eligible current-scope records.
Private expected strings are evaluation-only; no evaluator dependency certificate
is given to selection, representation or acquisition. Authored expected values
are released as feedback only for already executed development attempts.

## Workload and access

Construct independent development histories first, with randomized identifiers
and literal values. Each history contains an initial request, an exact repeat,
a leaf-value correction, a root dependency revision, another repeat and an old
still-valid request. Every episode exposes only its current archive and request.
Old revisions remain recoverable. Other-environment records remain in the raw
archive, but declared scope and highest-revision rules apply to **every** policy.
All ordinary source/code access is available; this is not a candidate-discovery
benchmark. Count archive scanning, representation building and filtered candidates.

An explicit ordinary parser-aware dependency-closure policy and validated answer
cache are the serious set-aware competitor. Full current-scope access is a complete
execution control. A learned scalar set energy searches variable-size subsets;
negative score is the same function, not a second mechanism. Compare exhaustive
discrete search with gradient optimization of the same coefficients/extension,
rounding and discrete repair. Do not call a naming change an EBM effect.

Development begins with an intentionally simple explicit-reference representation.
Diagnose native syntax it misses (defaults/escaping), acquisition versus search,
and variable evidence needs. Preserve that attempt, then adopt a grammar-aware
representation if the diagnosis warrants it. All policies may use the improved
public parser; do not cripple the ordinary alternative.

## Acquisition and boundaries

For earlier development episodes, execute bounded random subsets, ordinary closure
proposals, omissions and supersets. Record proposal origin, delivered IDs, actual
native output/error, complete feedback and work. This is investigator-designed
exploration with ordinary-policy proposals, not autonomous discovery or imported
benchmark support supervision. Fit the energy from successful/failed and shorter/
longer successful attempts, with an untrained same-initialization control.
Trainable weights persist; optimizer selection variables never persist.

Run development and freeze the developed claim, code, weights and protocol before
constructing fresh transfer histories. Later histories run in a new process.
Within a history, archive revisions and each policy's answer/source cache survive;
native parser state and transient optimizer state reset each episode. Frozen
weights receive no confirmation feedback updates. Compare frozen earlier-trained
weights with no-experience weights; do not equate static supervised ordering with
continuing experience. Here actual archive events/repeated obligations are authored.

Public runtime error or scope/currentness failure may trigger ordinary closure
repair; a hidden wrong-answer grade may not. Record first-attempt and repaired
completion separately. A cache entry is reusable only while every cited revision
is still current and the request matches. Report invalidations, retained correct
reuse, changed dependencies, and source omissions separately from execution.

## Smallest informative comparison and stopping

Start with 12 development histories. Diagnose failures before fixing the final
training/search settings. Reserve 12 fresh histories, generated only after freeze,
with independent seed/IDs/values and the same declared event families. The history,
not each correlated stage, is the unit of replication. No formal broad population
claim or requirement for a learned win. Native outcomes, subset evaluations,
gradient steps, executed label attempts, train steps/time, representation work,
delivered bytes, repeated work/cache reuse and repair must be published.

An LLM reader is deliberately not introduced in this phase: exact native execution
isolates selection and maintenance without another ambiguous natural-language
grader. This cannot establish primary-model reading or end-to-end assistant gains.
Close this phase on an explained acquisition/search/maintenance limit or useful
ordinary-method result, preserving failed runs. Any further reader experiment
requires a separately frozen interface and fresh material.
